# Existing "human typer" / "auto typer" tools for Google Docs — landscape as of 18 Nov 2026

Method note for the report writer: Chrome Web Store (CWS) figures below (users, rating, version, "Updated" date) were read directly from each listing's HTML on 2026-11-18 (US/English view). Feature descriptions on listings are vendor marketing copy and were not tested. GitHub figures (stars, last push, licence) come from the GitHub API on 2026-11-18; "technique" statements for open-source repos come from reading/grepping the repo source on that date. Nothing was installed or run. CWS user counts are rounded by Google ("60,000 users" means 60,000+).

## Which Chrome Web Store extensions exist, and what features and settings does each expose?

### Takeaway
The category is crowded (30+ listings found) but concentrated: Duey.ai's two listings (60,000 + 40,000 users) dominate, followed by Write It and Human Auto Typer (20,000 each), Natural Typist and Undetectable AI (10,000 each); everything else is under ~7,000 users and most are under 1,000. Nearly all expose the same core (paste text, WPM, typo rate with auto-correction, pauses, pause/resume, progress/ETA); the leaders differentiate on off-tab typing, multi-block placement, multi-sitting/scheduling, formatted typing, and Word/Slides/any-site support.

## Which open-source implementations exist on GitHub, and which technique does their source use?

### Takeaway
About a dozen small repos exist (largest has 25 stars); none is a de facto standard. Their source shows four distinct techniques: (1) synthetic `KeyboardEvent`s dispatched into Docs' hidden `.docs-texteventtarget-iframe`, (2) `chrome.debugger` + CDP `Input.dispatchKeyEvent` for trusted key events, (3) a multi-method cascade (beforeinput / synthetic paste / execCommand) verified by caret movement, and (4) OS-level keystrokes via pynput/pyautogui.

- Auto-Type exposes profiles Average (~52 WPM), Fast (~75 WPM), Slow (~25 WPM) and an advanced mode for base speed, timing variation, key-overlap (rollover) probability and error/correction rates; it models key-press hold duration (default mean 116.25 ms, SD 23.88 ms) with Gaussian sampling. Author's own caveats: "The Time predictions are very off" and it lacks "thinking" pauses. — [README](https://github.com/GitLitAF/Auto-Type/blob/main/README.md); [UserScript.js](https://github.com/GitLitAF/Auto-Type/blob/main/UserScript.js)
- Dripwriter Origin's source documents why Docs is hard: "Google Docs serves different editor builds to different users, and each build accepts a different subset of synthetic events"; "`execCommand(\"insertText\")` returns false on Docs' editing host"; "`dispatchEvent` returns true for 'an event was dispatched', not 'text landed'"; the text-event iframe "is a 1px offscreen keystroke buffer holding zero-width spaces; it never reflects document content"; "The document itself is painted to <canvas>". Hence "every mutation is applied speculatively and then verified against the one DOM signal that does move when Docs applies an edit: the caret." It also notes "Some Docs builds ignore `beforeinput` entirely and only apply synthetic paste events — and a paste whose content is whitespace-only is silently dropped", so whitespace is paired with the next printable character. — [src/lib/insertion.ts](https://github.com/alexey-max-fedorov/dripwriter-origin/blob/master/src/lib/insertion.ts); [src/lib/harness/docs.ts](https://github.com/alexey-max-fedorov/dripwriter-origin/blob/master/src/lib/harness/docs.ts)
- Dripwriter Origin features: 20–150 WPM, neighbor-key typos auto-corrected, "false-start words pulled from nearby context and fully deleted", breaks at sentence boundaries, a diagnostics "Run Test" mode to verify which event paths work; explicitly "not affiliated with... Dripwriter, LLC or the commercial service at dripwriter.com". — [README](https://github.com/alexey-max-fedorov/dripwriter-origin/blob/master/README.md)
- Ghost Typer README: "uses the Chrome DevTools Protocol (CDP) to send trusted keyboard events directly to the browser — the same type of events that are generated when you physically press keys"; Gaussian timing; typo engine continues 1–2 characters before "noticing"; ~0.3% per-character chance to delete the last 3–8 characters and retype; rare 20–60 s breaks; Markdown input converted to bold/italic/headings/bullets. — [README](https://github.com/Leonxlnx/ghost-typer/blob/main/README.md); [background.js](https://github.com/Leonxlnx/ghost-typer/blob/main/background.js)
- TYPIST README lists "Native Messaging: Python host (pyautogui) for Google Docs where JS events fail" and says "For Google Docs and Google Slides, you need the native messaging host" (Windows `install_host.bat`); 5 speed levels (150–300 ms down to 15–50 ms per keystroke), 5 error rates (0–15%), "Time Limit Mode", 1–4 s thinking breaks every 15–40 characters. — [README](https://github.com/novafova/typist/blob/main/README.md)
- eztypr README explains the page-world requirement: the dispatch "needs to be part of the actual DOM of the Google Doc instead of being an external 'content' script... due to world separation of content script"; positions itself against Duey ("free and open source, no subscription") and as designed to get around "version history review extensions like Draftback". - TrickleType README: duration-based pacing only (1 minute to 4 hours or custom), text "spread evenly across the whole duration"; "Leave the Google Docs tab open while it runs. You can switch to other tabs and other windows, but closing the tab stops the session"; and "The Chrome Web Store copy is currently stuck on an older build (1.0.0). If text is not appearing in your document — only blank lines — install from here instead." — [README](https://github.com/heyitsR1/TrickleType/blob/main/README.md)
- TypeCloak presets: Slow 25 / Casual 45 / Normal 65 / Quick 90 / Fast 120 WPM with paired variability and typo rates (2–8%); duration target with "drift correction"; "Fatigue Curve" (up to 35% slower by the end); "Smart Error Zones" (typo probability peaks mid-word); "Stealth Mode" (0.8–2.8 s reading pauses after paragraphs); supports Docs, Slides, Forms, Canvas, Blackboard, Moodle. — [README](https://github.com/Crispy252/TypeCloak/blob/main/README.md); [message-handler.js](https://github.com/Crispy252/TypeCloak/blob/main/extension/background/message-handler.js)
- DocuSim behaviours: inter-sentence pauses scaled by sentence complexity, word-frequency-based delays (Brown corpus), burst typing, short and long breaks, capitalization errors, and uncorrected grammar/punctuation errors; "interacts directly with your active window". — [README](https://github.com/7afi/DocuSim-Google-Docs-Revision-History-Simulator/blob/main/README.md)
- TheBrainAir Human-Typer config: wpm 62, accuracy 0.93, consistency 0.69 (MonkeyType-style stats), think-pause chance 0.02, burst chance 0.15; "Requires X11. - Outside GitHub, the Greasy Fork userscript **"Human-Typer (Enhanced v1.8 - Advanced Algo) - Google Docs & Slides"** by Integrace: MIT, 1,694 total installs (3/day), created 2023-08-27, last updated 2025-04-09; lower/upper per-character delay bounds in ms, ETA, stop button, typos with auto-correction; adds a button next to "Extensions" in the Docs menu; notes "Edit history updates slowly, so validating the typing may take at least 15 minutes". — [Greasy Fork](https://greasyfork.org/en/scripts/474038-human-typer-automatic-google-docs-slides)

### Inferences
- Synthetic-event dispatch into `.docs-texteventtarget-iframe` is the most common and simplest technique (5 of the code-bearing repos), but it produces untrusted events and depends on an internal Docs class name; Dripwriter Origin's comments and TrickleType's "only blank lines" bug suggest this path is fragile across Docs builds. Inferred from source comments and README notes, not from testing.
- The `chrome.debugger` route gives trusted events and is used by the more feature-ambitious tools (ghost-typer, TypeCloak, and DocTyper per its listing), at the cost of the `debugger` permission and Chrome's "is debugging this browser" banner (the banner is general Chrome behaviour, not something the repos state).
- No working Apps Script implementation was found; the one repo naming Apps Script is empty.
- No open-source repo implements formatted typing beyond Ghost Typer's Markdown conversion, and none implements cross-day scheduling.

### Gaps
- The Greasy Fork script's source was not read, so its dispatch technique is unconfirmed.
- Smaller 0-star repos (atomik-avocado/AutoTyper-Lite, sohamgoswami7156/Autoquill, HelloThere93/typingtool, Connor-Briand/human-type-ai) were listed by the GitHub search but not inspected.
- GitHub code search (as opposed to repo search) was not used, so userscripts/gists embedding the same technique may be missed.
- Technique was determined by static grep, not by running the extensions; which code path actually fires on current Docs builds is unknown.

## Which tools are NOT extensions, and what trade-offs do they advertise?

### Takeaway
Non-extension options are few: one commercial cloud "drip" service (dripwriter.com) that connects to the user's Google account and spreads text over 30 minutes to a week, Duey Pro's laptop-closed "Sessions", and several Python/desktop keystroke injectors. No Apps Script product and no other OAuth/Docs-API web app was found.

### Cited Findings
- **Dripwriter (dripwriter.com)**: tagline "AI That Writes Slowly, Like You"; user pastes text (demo shows a 1,500-word input limit), picks a duration (30 minutes to 1 day or custom; Pro up to a week) and connects a new or existing Google Doc; "Dripwriter connects securely to your Google account"; "It only interacts with the specific document you select — never any others"; "Keep dripping while you're away"; pacing follows the user's timezone; free tier has daily word caps and "very long periods of inactivity may pause the session automatically"; Pro offers unlimited usage, background drips and priority processing (price not shown on the page). It does not simulate typos: "Dripwriter never rewrites, edits, or modifies your text", and "Dripwriter is not an AI humanizer and does not bypass AI detectors". Claims use in "175+ countries". — [dripwriter.com](https://www.dripwriter.com)
- **Duey Pro "Sessions"**: "schedule a doc to be typed over hours or days, even with your laptop closed" — part of the $9.99/month or $60/year Pro plan; the listing also discloses handling "Authentication information". — [CWS listing](https://chromewebstore.google.com/detail/ilamopeagajnekeaogejpdmffneankjf)
- **EchoType** is a hybrid: text and settings live in a web app (echo-type.com) and a companion extension performs the typing locally. — [CWS listing](https://chromewebstore.google.com/detail/jdhfoiinbeockjeamecpgnajknenfbkf)
- **Desktop keystroke injectors**: DocuSim (pynput), TheBrainAir/Human-Typer (pyautogui/pynput), fuzzerson/anti-anti-ai (prebuilt binaries), and novafova/typist's native host (pyautogui). Stated trade-offs: types into whatever window is active ("Switch to your target window during the countdown"), plain text only, Mac needs accessibility permission, pyautogui failsafe "move mouse to top-left corner to abort", Linux needs X11, Windows may need administrator. — [DocuSim README](https://github.com/7afi/DocuSim-Google-Docs-Revision-History-Simulator/blob/main/README.md); [Human-Typer README](https://github.com/TheBrainAir/Human-Typer/blob/main/README.md); [anti-anti-ai](https://github.com/fuzzerson/anti-anti-ai); [typist README](https://github.com/novafova/typist/blob/main/README.md)
- **Userscripts** (Tampermonkey): GitLitAF/Auto-Type and Greasy Fork Human-Typer require installing a userscript manager and, for Auto-Type, enabling Chrome Developer Mode. — [Auto-Type README](https://github.com/GitLitAF/Auto-Type/blob/main/README.md); [Greasy Fork](https://greasyfork.org/en/scripts/474038-human-typer-automatic-google-docs-slides)
- A web search for a sign-in-with-Google cloud typer beyond Dripwriter returned only extensions and userscripts. — [TypeFlow CWS result](https://chromewebstore.google.com/detail/typeflow/heldgoophbicegdodimdkbjcnajbkdhb); [Docs Dripper](https://chromewebstore.google.com/detail/docs-dripper/hcgfpiceofjepdhfahaebbjiaeggekei)

### Inferences
- Dripwriter and Duey Sessions almost certainly write server-side through Google's Docs API under an OAuth grant (the only way to edit with the user's machine off). Neither vendor states "OAuth" or "Docs API" in the material reviewed, so this is inferred.
- Trade-off pattern, inferred from the above: cloud/API tools win on unattended multi-day runs and no open tab, but work in chunks rather than keystrokes (Dripwriter advertises no typos or corrections) and need Google-account access; extensions give per-keystroke realism but need the tab (and usually the machine) kept open; desktop injectors produce genuine OS-level key events and work in any app, but monopolise keyboard focus so the computer cannot be used during the run, and have no awareness of the document.
- The name collision "Dripwriter" (commercial cloud service) versus "Dripwriter Origin" (free extension, explicitly unaffiliated) is a likely source of user confusion.

### Gaps
- Dripwriter's and Duey Pro's actual mechanism, OAuth scopes requested, and insertion granularity (per character vs per word/sentence) were not verified.
- Dripwriter Pro pricing and user numbers are not published on the page reviewed.
- No AutoHotkey-based tool specifically for Docs was found in the searches run; AutoHotkey forums and YouTube descriptions were not searched.
- Product Hunt and YouTube demo descriptions were not reviewed.

## What feature set is table stakes versus differentiating?

### Takeaway
Table stakes: paste-in text box, WPM/speed control with randomised per-key timing, adjacent-key typos that get backspaced and fixed, punctuation/sentence/paragraph pauses, pause/resume/stop, and a progress/ETA indicator. Differentiators: off-tab reliability, multi-sitting and scheduled/cloud sessions aligned to Docs' version-history behaviour, formatted typing, multi-block placement, richer "revision" behaviours (rewording, false starts, draft mode), trusted-event input, and coverage of Slides/Word/any site.

### Inferences
- Table stakes (present in essentially every listing reviewed): text paste box; speed control; randomised inter-key timing; adjacent-key typo + backspace correction with a rate slider; pauses at punctuation/sentence/paragraph; start/pause/resume/stop; progress bar or ETA; settings persistence; Google Docs support.
- Common but not universal: longer "away" breaks; duration-target pacing; Google Slides support; keyboard shortcuts; dark mode; presets.
- Differentiating (few tools, often paid): full-speed off-tab/background typing; multi-sitting sessions tied to the 30-minute version-history rule; cloud/laptop-closed scheduling; formatted typing; multi-block and multi-document runs; semantic revisions (rewording, false starts, draft-then-final); trusted key events via `chrome.debugger`; self-verifying insertion with diagnostics; Word/PowerPoint Online and arbitrary-site support; in-product version-history replay; non-QWERTY layouts and UI localisation.
- The monetisation line in this market sits at formatting, scheduling/multi-sitting depth, and multi-document use, not at the basic typing loop, which is free nearly everywhere.
